Move handling rules out of core into the new `@opsorama/objects/handling` entry, which loads no Three.js code. `createHandlingState`, `createMoveMode`, `handlingFits`, `validateHandlingProfile`, `validateAssetHandling`, `HANDLING_FAMILIES` and every handling type (`AssetHandling`, `HandlingState`, `ReceptacleTarget`, `ResolvedTarget`, `MoveMode` and the rest) now come from `@opsorama/objects/handling` instead of `@opsorama/core`; `bindMoveMode` moves there from `@opsorama/three`. The behavior runner's `handling` option becomes the generic `itemPolicy` option: pass `itemPolicy: handlingItemPolicy(handling)` for the same checked pick-ups and put-downs. Core declares the `ItemPolicy` interface (`addCarrier`, `placements`, `carried`, `exchange`, `subscribe`, `itemChanges`) with `ItemCheck`, `ItemViolation`, `ItemPlace`, `ItemDestination`, `ItemExchange` and `ItemPolicyPlacement`; `putOn` accepts an `ItemPlace` (`{ receptacle, ... }`), whose extra fields the handling entry declares by augmentation. `RouteViolationCode` no longer includes the handling codes; a `RouteViolation` from a policy carries the policy's own string code. The renderer's `setMoveTargets(targets, onPick)` becomes the generic `setPickTargets(targets: PickTarget[] | null, onPick?: (target, index) => void)`, where a `PickTarget` is a box on a node anchor (`node`, `anchor`, `offset`, `size` as [width, height, depth]); `createMoveTargetObject`, `highlightMoveTarget` and `MoveTargetMarker` become `createPickTargetObject`, `highlightPickTarget` and `PickTargetMarker`.
