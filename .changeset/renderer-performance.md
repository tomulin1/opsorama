Make the renderer do only the work a change needs. Node signatures are computed once per node object and dropped only when the theme or palette changes, so an `upsert` serializes just the changed node; a change of the selection, zoom or camera skips the node loop, and hover is no longer a store sync: only the nodes that gain or lose the selection or hover change their brackets, glow and labels. Cleaning a node before its rebuild walks only its own model, so a theme change is linear in the scene size, and instanced batches remove members in constant time. Pointer moves are resolved once per animation frame with one shared raycast for hover, hover peeking, pick targets and `onPointer`; a resting mouse is cast again only when the camera moved, and a press, release and click at one position share a raycast. Labels are measured once (again after a selection class change, a resize, a font load or a theme change), keep their placement order between store changes, test collisions against nearby labels only, write the DOM only where something changed, and skip layout in frames where nothing moved. The renderer still draws every frame while the page is visible, also while its canvas is scrolled out of view, so the canvas can be read at any time (exports, screenshots); a host that wants to save work while a scene is off-screen can unmount it, or set `SceneSettings.paused` to stop its motion. The ground extent is measured once per node list instead of every frame, and controller contexts are reused across frames. New: `getDiagnostics().work` (`RendererWork`) counts syncs, node syncs, signatures, node updates, builds, scene raycasts, label measures and label layouts since mount. React's `SceneCanvas` and Vue's `SceneCanvas` forward pointer events to the renderer only when a handler or `pointer` listener was present at mount (a changed React handler still applies without a remount); the first handler added after a mount without one remounts the renderer once.
