Move model-specific node fields into one `AssetNode.options` field. Core declares `AssetOptions` as an open map, validates only that it is plain JSON-like data and deep-freezes it in the store; `heatEnabled`, `waterRunning`, `fillLevel`, `forks`, `person`, `building`, `contents`, `display`, `measurement` and `surfaceLabel` leave `AssetNode` and become `options.<name>` (for example `node.forks` → `node.options.forks`). Their types and helpers move from `@opsorama/core` to `@opsorama/objects`: `ForkMotion`, `ForkPose`, `ForkMove`, `FORK_LIMITS`, `validateForkMotion`, `finalForkPose`, `forkPoseAt`, `PERSON_ASSETS`, `isPersonAsset`, `PersonOptions`, `PERSON_FIGURES`, `PERSON_HAIR_COLORS`, `personHairColor`, `ContainerContents`, `ContentLine`, `validateContents`, `projectContents`, `contentsLabel`, `DisplayReading`, `validateDisplay`, `formatDisplay`, `Measurement`, `MeasurementBand`, `resolveMeasurement`, `formatMeasurement`, `SurfaceLabel`, `validateSurfaceLabel` and `validateOperatingProperties`. `@opsorama/objects` augments `AssetOptions` with these typed options, and every catalog factory carries `validate`, which rejects an option the asset does not accept (naming the assets that accept it) and checks values and the rules between options and node fields. `createSceneStore(definition, settings, { validateAsset })` adds a store hook for asset nodes; `assetValidator(registry)` from `@opsorama/three` applies a registry's checks there. `AssetFactory` may carry `validate`, which the renderer calls before building, and the renderer takes label text from the factory hint `userData.labelText` (with `userData.labelWrap`) instead of reading contents or measurements. Descriptor customization fields name moved options as `options.<name>`. The Vue `Asset` component replaces the per-model props with one `options` prop. Options must be finite where they are numbers, because JSON has no NaN or Infinity. Catalog `validate` also runs the model's own pre-build checks (readout reading kind and variant, gauge variant, parcel and building rules), rejects counts on assets without a count definition and checks footprint ranges, so the store hook rejects every node the factory would reject.
